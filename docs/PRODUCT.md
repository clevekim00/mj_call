# 제품 기획 — mj_call

2026-11-03. 말이음의 재활 훈련과 목적이 다른 생활 의사소통 지원을 독립 앱으로 분리한다.

## 사용자와 목표
마비말장애 사용자가 기관·고객센터에 필요한 질문을 전달하고, 답·서류·제출 방법·기한·담당 부서·접수번호·회신 예정일을 확인하도록 돕는다. 음성 입력이나 빠른 타이핑을 필수로 하지 않는다.

## 확정 사항
- 이름: mj_call. GitHub public, MIT.
- Flutter 사용 안 함. Windows PC, macOS, iPhone, iPad, Android 네이티브 앱.
- 별도 전화기로 사용자가 발신하고 스피커폰을 켠다. 보조 기기의 마이크와 스피커가 통화 상대와 소리를 주고받는다.
- 첫 대상: 기관·고객센터 문의.
- 초기 수동 보조: 통화 준비 → 직접 입력·준비 문장 발화 → 선택적 녹음 → 수동 결과 기록 → 재생·삭제.
- 최종 목표: 목적·허용 조건에 따라 AI가 상대를 듣고 대화를 진행하며 새 결정은 사용자에게 확인.

## 메뉴
독립 앱의 첫 화면이 ‘기관·고객센터 통화 도우미’다. 준비·통화 조작·메모·저장 기록에 직접 접근한다. 말이음의 오늘·훈련·게임 메뉴를 가져오지 않는다. 현재 네이티브 초기 UI는 한 화면에 이 흐름을 배치했다. 이후 준비/통화/기록 3화면으로 분리할 수 있다.

## 완료 기준
질문별 답이 확인돼야 ‘답변 확인’이다. 연결 성공·접수·회신 대기·최종 해결은 구분한다. 현재 결과는 사용자가 지정하며 자동 판정하지 않는다.

## 자동화 범위와 제한
AI가 시행할 행위와 전달 가능한 정보는 사용자가 사전에 설정한다. 새 비용·신청·취소·민원 제출·개인정보 공개는 별도 승인. 인증번호·비밀번호는 자동 처리하지 않는다. ARS 버튼은 전화기에서 사용자가 누른다. 의료 판단·금융 거래·응급 신고 자동화는 초기 범위 밖이다.

## 품질·접근성
큰 버튼, 글자 확대, 스크린리더, 키보드 조작, 영구적인 말하기 중지 접근성을 검증한다. 동작 중 자동 화면 전환과 제한시간을 최소화한다. 두 기기의 에코·겹침·지연은 실제 전화기 조합으로 평가한다.

## 개인정보
초기 구현은 AI 서버로 전송하지 않는다. 음성·메모는 로컬 저장소에 남는다. 녹음 전 안내·허락 확인은 제품 정책으로 둔다. OS 백업·음성서비스 정책까지 포함한 출시 전 검토가 필요하다. 정해진 보관기간 자동 삭제와 암호화 저장은 미구현이다. 법적 허용 여부를 모든 상황에 대해 보장하지 않는다.
